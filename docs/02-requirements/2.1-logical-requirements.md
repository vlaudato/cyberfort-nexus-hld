# 2.1 Logical Requirements — System Functionality

## 2.1.0 Traffic Capture & Distribution

- **FR-SYS-001**: The system MUST capture all mirrored IP traffic from the organisation's gateway switch and MUST ensure that each detection sensor receives the traffic relevant to its function.

## 2.1.1 Threat Detection Sensors

### File Analysis (FA)

- **FR-FA-001**: The FA Engine MUST store **any** inbound file received.
- **FR-FA-002**: The FA Engine MUST store **any** inbound email received.
- **FR-FA-003**: The FA Engine MUST submit **any** inbound file or email to a 3rd-party system for anti-virus scanning.
- **FR-FA-004**: The FA Engine MUST receive results from the anti-virus scanner and MUST store the scan results.
- **FR-FA-005**: The FA Engine MUST consider a file/email as a threat if the 3rd-party scan returns a verdict of **malicious** or **suspicious**.
- **FR-FA-006**: If a file/email is considered a threat, the system MUST create an alert and MUST forward it to the Automatic Cyber Investigator (ACI).
- **FR-FA-007**: If a file/email is not considered a threat, the system MUST automatically delete the stored file/email.
- **FR-FA-008**: The stored files/emails considered as threats MUST have a retention period of 3 months. At the end of this period, the system MUST automatically delete them.
- **FR-FA-009**: The stored logs related to the file analysis MUST have a retention period of 1 year. At the end of this period, the system MUST automatically delete the logs.

### Command & Control Detection (C&C)

- **FR-CC-001**: The C&C Detection Engine MUST analyze all outbound traffic metadata.
- **FR-CC-002**: The C&C Detection Engine MUST submit outbound traffic metadata to the machine learning model and MUST receive a confidence score indicating the probability of the analyzed traffic being C&C activity.
- **FR-CC-003**: The C&C Detection Engine MUST consider traffic as suspected C&C activity when the confidence score exceeds 0.70.
- **FR-CC-004**: If outbound traffic is considered suspected C&C activity, the analysis result MUST be logged.
- **FR-CC-005**: If outbound traffic is considered suspected C&C activity, the system MUST create an alert and MUST forward it to the ACI.
- **FR-CC-006**: The stored logs related to the C&C analysis MUST have a retention period of 1 year. At the end of this period, the system MUST automatically delete the logs.

### Network Forensics (NF)

- **FR-NF-001**: The NF Engine MUST store all the IP traffic metadata.
- **FR-NF-002**: The IP traffic metadata MUST include Source IP, Destination IP, Source Port, Destination Port, Protocol and Timestamp.
- **FR-NF-003**: The IP traffic metadata MUST be indexed and searchable.
- **FR-NF-004**: The retention period of the IP traffic metadata MUST be 3 months. At the end of this period, the system MUST automatically delete them.

## 2.1.2 Automatic Cyber Investigator (ACI)

- **FR-ACI-001**: The ACI MUST access all the alerts generated by the FA and C&C engines.
- **FR-ACI-002**: The ACI MUST forward all the alerts generated by the FA and C&C engines to the Investigation Portal (InvP).
- **FR-ACI-003**: The ACI MUST query the NF data.
- **FR-ACI-004**: The ACI MUST link related alerts from the three engines using shared indicators such as endpoint IP addresses and time proximity.
- **FR-ACI-005**: The ACI MUST create an investigation that combines correlated alerts and NF data, and MUST forward it to the InvP.

## 2.1.3 Investigation Portal (InvP)

- **FR-INVP-001**: The InvP MUST display all alerts and investigations forwarded by the ACI.
- **FR-INVP-002**: The InvP MUST only display to a SOC analyst the alerts and investigations that are unassigned, owned by them, or created by them.
- **FR-INVP-003**: The InvP MUST allow SOC analysts to take ownership of unassigned alerts and investigations.
- **FR-INVP-004**: The InvP MUST allow SOC analysts to read all NF data for manual investigation.
- **FR-INVP-005**: The InvP MUST allow SOC analysts to view the details of alerts and investigations, including source engine, verdict, associated metadata, timeline of correlated alerts, and network recordings.
- **FR-INVP-006**: The InvP MUST NOT allow SOC analysts to edit alerts and investigations created by the ACI.
- **FR-INVP-007**: The InvP MUST allow SOC analysts to create their own investigations by manually linking multiple alerts and NF data.
- **FR-INVP-008**: The InvP MUST allow SOC analysts to edit investigations created by them.
- **FR-INVP-009**: The InvP MUST provide dashboards and reports regarding open alerts and investigations.
