# 2.5 Scalability Requirements

Scalability determines how the system will handle increased user loads or larger datasets over time.

- **NFR-010**: A single software baseline MUST support all three sizing tiers. Moving between tiers MUST be achievable by adding compute and/or storage resources (horizontal scale-out) only, with no code changes or re-architecture.
- **NFR-011**: The system MUST support in-place expansion to the next tier without loss of retained data (*[NFR-008](2.4-performance-capacity.md#storage)*) and with expansion downtime counting withing the 99.9% availability budget (*[NFR-001](2.3-availability-recovery.md)*).
- **NFR-012**: Response Time requirements *[NFR-005](2.4-performance-capacity.md#response-time)* and *[NFR-006](2.4-performance-capacity.md#response-time)* MUST be met at every tier, with the datastore at maximum retention volume *[NFR-008](2.4-performance-capacity.md#storage)*.
- **NFR-013**: The system is not required to scale beyond 50 concurrent users (*[NFR-009](2.4-performance-capacity.md#concurrent-users)*) or 10000 endpoints.
