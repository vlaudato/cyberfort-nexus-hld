# 3.2 Processes

The following sequence diagrams describe the main runtime processes and the order in which components interact. Dashed arrows represent asynchronous event delivery or returned responses; solid arrows represent direct requests, data writes, or internal processing.

### 3.2.1 File Analysis

Capture & Flow Export reconstructs inbound POP3 and FTP streams, stores each extracted object, and publishes only its reference. File Analysis scans each object immediately and always stores the scan report. Threatening content is retained and raises an alert; other content is deleted (FR-FA-001 through FR-FA-009, ADR-006).

```mermaid
sequenceDiagram
    autonumber
    participant GW as GW Switch
    participant CFE as Capture and Flow Export
    participant BS as Bucket Storage
    participant LOG as Durable Event Log
    participant FA as File Analysis
    participant AV as 3rd-party Antivirus
    participant CDB as Columnar Database
    participant PB as Portal Backend
    participant RDB as Relational DB
    participant ACI as ACI

    GW->>CFE: Mirror inbound POP3 or FTP traffic
    CFE->>CFE: Reassemble stream and extract object
    CFE->>BS: Store file or complete e-mail
    CFE-->>LOG: Publish file.received with object key
    LOG-->>FA: Deliver file.received
    FA->>BS: Fetch object by key
    BS-->>FA: Return object content
    FA->>AV: Submit object for scanning
    AV-->>FA: Return verdict
    FA->>CDB: Append scan report with 1-year retention

    alt Verdict is malicious or suspicious
        Note over BS: Retain threatening object for 3 months
        FA-->>LOG: Publish alert.raised
        Note over LOG,ACI: Portal Backend and ACI consume independently
        LOG-->>PB: Deliver alert.raised
        PB->>RDB: Persist alert
        LOG-->>ACI: Deliver alert.raised
    else Object is not considered a threat
        FA->>BS: Delete object
    end
```

### 3.2.2 Command & Control Detection

Command & Control consumes outbound flow metadata in micro-batches and scores each batch with its in-process machine-learning model. Only flows whose score exceeds 0.70 produce a retained detection and an alert (FR-CC-001 through FR-CC-006, ADR-004).

```mermaid
sequenceDiagram
    autonumber
    participant CFE as Capture and Flow Export
    participant LOG as Durable Event Log
    participant CC as Command and Control
    participant CDB as Columnar Database
    participant PB as Portal Backend
    participant RDB as Relational DB
    participant ACI as ACI

    CFE-->>LOG: Publish outbound flow records

    loop Each available micro-batch
        LOG-->>CC: Deliver batch of outbound flows
        CC->>CC: Score batch with in-process model

        alt Flow score exceeds 0.70
            CC->>CDB: Append detection with 1-year retention
            CC-->>LOG: Publish alert.raised
            Note over LOG,ACI: Portal Backend and ACI consume independently
            LOG-->>PB: Deliver alert.raised
            PB->>RDB: Persist alert
            LOG-->>ACI: Deliver alert.raised
        else Flow score is 0.70 or lower
            Note over CC: Do not create a detection or alert
        end
    end
```

### 3.2.3 Automatic Investigation Creation

The ACI consumes every raised alert, queries related network flow data, correlates evidence using shared indicators and time proximity, and creates an investigation. The correlated evidence is copied into an immutable snapshot so it remains reviewable after the source flow records expire (FR-ACI-001 through FR-ACI-005, ADR-005).

```mermaid
sequenceDiagram
    autonumber
    participant LOG as Durable Event Log
    participant ACI as ACI
    participant CDB as Columnar Database
    participant RDB as Relational DB

    LOG-->>ACI: Deliver alert.raised
    ACI->>CDB: Query related flows by indicators and time range
    CDB-->>ACI: Return matching network flow records
    ACI->>ACI: Correlate consumed alerts and flow records
    ACI->>RDB: Create investigation and immutable evidence snapshot
    Note over RDB: Available to the Portal, ACI-generated content remains read-only
```

### 3.2.4 Manual Investigation Creation

A SOC analyst can inspect and take ownership of an alert, search network flow data, and create an investigation from selected evidence. At creation time, the Backend copies the selected alerts and flow records into an immutable evidence snapshot. The analyst can continue editing the investigation they created, while the captured evidence remains frozen (FR-INVP-003/004/005/007/008, ADR-005).

```mermaid
sequenceDiagram
    autonumber
    actor SOC as SOC Analyst
    participant FE as Portal Frontend
    participant PB as Portal Backend
    participant RDB as Relational DB
    participant CDB as Columnar Database

    SOC->>FE: Open an alert
    FE->>PB: Request alert details
    PB->>RDB: Read alert
    RDB-->>PB: Return alert and metadata
    PB-->>FE: Display alert details

    SOC->>FE: Take ownership of alert
    FE->>PB: Submit alert ownership request
    PB->>RDB: Assign alert to analyst
    RDB-->>PB: Confirm alert ownership
    PB-->>FE: Display analyst as alert owner

    SOC->>FE: Search network flow data
    FE->>PB: Submit search criteria
    PB->>CDB: Query flows by filters and time range
    CDB-->>PB: Return matching flow records
    PB-->>FE: Display search results

    SOC->>FE: Select alert and flow records and create investigation
    FE->>PB: Submit investigation creation request
    PB->>RDB: Read selected alert evidence
    RDB-->>PB: Return selected alerts
    PB->>CDB: Read selected flow evidence
    CDB-->>PB: Return selected flow records
    PB->>RDB: Store investigation and immutable evidence snapshot
    RDB-->>PB: Confirm investigation creation
    PB-->>FE: Display created investigation

    loop As the analyst refines the investigation
        SOC->>FE: Edit investigation fields
        FE->>PB: Submit investigation update
        PB->>RDB: Update editable investigation data
        RDB-->>PB: Confirm update
        PB-->>FE: Display updated investigation
    end

    Note over PB,RDB: The evidence snapshot is not modified
```

### 3.2.5 Review and Ownership of an Automatic Investigation

An analyst can open an ACI-created investigation, review its correlated timeline and evidence, and take ownership of it. Ownership metadata can change, but the ACI-generated investigation content remains immutable (FR-INVP-002/003/005/006).

```mermaid
sequenceDiagram
    autonumber
    actor SOC as SOC Analyst
    participant FE as Portal Frontend
    participant PB as Portal Backend
    participant RDB as Relational DB

    SOC->>FE: Open dashboard
    FE->>PB: Request visible alerts and investigations
    PB->>RDB: Query unassigned, owned, or analyst-created items
    RDB-->>PB: Return visible items
    PB-->>FE: Display dashboard

    SOC->>FE: Open ACI-created investigation
    FE->>PB: Request investigation details
    PB->>RDB: Read investigation and evidence snapshot
    RDB-->>PB: Return investigation and correlated timeline
    PB-->>FE: Display read-only ACI content

    SOC->>FE: Take ownership
    FE->>PB: Submit ownership request
    PB->>RDB: Assign investigation to analyst
    RDB-->>PB: Confirm ownership
    PB-->>FE: Display analyst as owner

    Note over SOC,RDB: Ownership changes, ACI-generated content does not
```

### 3.2.6 Network Forensic Ingestion and Query

Network Forensic consumes both inbound and outbound flow records in batches and appends them to the Columnar Database, where they remain indexed and searchable for 3 months. The ACI queries this data for automated correlation, while the Portal Backend queries it for manual investigation (FR-NF-001 through FR-NF-004, FR-ACI-003, FR-INVP-004).

```mermaid
sequenceDiagram
    autonumber
    participant CFE as Capture and Flow Export
    participant LOG as Durable Event Log
    participant NF as Network Forensic
    participant CDB as Columnar Database
    participant ACI as ACI
    participant PB as Portal Backend

    CFE-->>LOG: Publish inbound and outbound flow records

    loop Each available batch
        LOG-->>NF: Deliver flow-record batch
        NF->>CDB: Append and index flow records
    end

    Note over CDB: Retain searchable flow records for 3 months
    Note over ACI,PB: Automated and manual queries are independent

    ACI->>CDB: Query flows by indicators and time range
    CDB-->>ACI: Return matching flow records

    PB->>CDB: Query flows by filters and time range
    CDB-->>PB: Return matching flow records
```
