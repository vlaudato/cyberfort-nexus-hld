
# 3.4 Upgradability

The initial release has no backward-compatibility obligation because no previous CyberFort Nexus release, persisted data format, or public interface has been identified (Section 2.9).

Components are packaged independently and should be replaceable without redesigning the complete system (NFR-022). Before a future release, compatibility and migration requirements must be defined for event formats, persisted data, configuration, and interfaces. Data-store changes require an explicit migration and rollback procedure, while event producers must remain compatible with the consumers present during a staged upgrade. Backups and rollback procedures must be validated before deployment.

The machine-learning model is upgraded together with the Command & Control component because the model runs inside that process (ADR-004).
